## 1. 背景与目标

### 1.1 背景

`PPTGenerator` 仓库目前只有 `demo.html`（MediaKit 广告投放报告编辑器原型，3550 行），没有任何：

- README / PROJECT.md / 立项信息
- CHANGELOG / 迭代记录
- 工作流约定（何时更新文档）

用户希望"伴随着迭代记录项目的立项信息以及 changelog 文档"——即建立项目文档基线 + 让后续每次会话自动追加 changelog。

### 1.2 目标

- **G1**：建立立项信息文档，让任何新会话/新人 5 分钟内能看懂项目背景、范围、技术栈、当前状态、后续计划
- **G2**：建立 changelog 文档，按日期 + 中文分类记录每次代码变更
- **G3**：写入一条工作流硬规则，让"会话末自动追加 changelog"跨会话生效（不依赖记忆）

### 1.3 非目标

- 不搭建构建系统 / 包管理（独立议题）
- 不写产品功能设计（产品本身已有 `2026-06-25-ppt-generator-design.md`）
- 不为外部读者做美化（精简、面向自己）

## 2. 方案对比与选择

| 路径 | 文件数 | 工作流保障 | 选/否 |
|---|---|---|---|
| A. `docs/PROJECT.md` + `docs/CHANGELOG.md` + `CLAUDE.md` | 3 | CLAUDE.md 强制跨会话生效 | ✅ 选 |
| B. 仅 `docs/PROJECT.md` + `docs/CHANGELOG.md` | 2 | 无，依赖手动提醒 | ✗ 几周后规则失效 |
| C. PROJECT.md + ROADMAP.md + CHANGELOG.md | 3 | 拆分违背"精简版"原意 | ✗ |

**选 A**：CLAUDE.md 是 Claude Code 在每个会话自动加载的项目级规则文件，把"会话末自动追加 changelog"写入其中是确保承诺落地的成本最低方式。

## 4. 各文件内容设计

### 4.1 `CLAUDE.md`（根目录）

精简硬规则文件，结构：

1. **项目一句话**：MediaKit 广告投放报告编辑器
2. **文档入口**：指向 `docs/PROJECT.md` 和 `docs/CHANGELOG.md`
3. **工作流硬规则**：
   - 会话末自检：若本次产生代码/文件变更 → 必须追加 `docs/CHANGELOG.md` 一条
   - 阶段变化（里程碑达成、范围调整）→ 更新 `docs/PROJECT.md` 的"当前状态"和"后续计划"
4. **Changelog 写入格式**：
   - 顶层按日期分组：`## YYYY-MM-DD`
   - 二级分类：`### 新增 / 变更 / 修复 / 重构`
   - 三级条目：一行简述 + 关键文件路径（`file:line` 格式）

### 4.2 `docs/PROJECT.md`（立项信息，精简版 5 字段）

| 字段 | 初始内容来源 |
|---|---|
| **项目背景与目标** | 从 demo.html 标题、组件类型、示例项目名（"美妆品牌Q4投放复盘"）反推业务场景与产品目标 |
| **范围** | 列出已实现功能（三栏布局、业务组件库 5 类、基础组件、撤销重做、页面增删）+ 未实现占位（导出、项目列表） |
| **技术选型** | 纯前端单文件、Google Fonts、SVG 图标、CSS 设计 tokens、`state` 全局对象 + history 栈 |
| **当前状态** | v0.1 原型；3 个示例页面；无构建/持久化/版本号 |
| **后续计划** | 待用户补充（设计稿里已留导出、项目列表、协作等占位） |

- 初始化项目文档体系：`docs/PROJECT.md` + `docs/CHANGELOG.md` + `CLAUDE.md`

## 5. 更新工作流（详细）

### 5.1 触发条件

每次会话即将结束时，自检本次会话是否产生了**任意**以下变更：

- 新建/修改/删除代码文件
- 新建/修改/删除配置文件
- 重命名/移动文件
- 修改 demo.html

若是 → 触发 changelog 追加。若否（纯对话/纯研究）→ 不追加。

### 5.2 写入规则

- **同一日已有 `## YYYY-MM-DD` 标题** → 在其下追加 `### 分类` 与条目
- **同日同分类** → 在该分类下追加新条目，不重复创建分类标题
- **跨日** → 在文件顶部（紧邻介绍段）新建 `## YYYY-MM-DD` 标题
- **条目顺序**：新增 → 变更 → 修复 → 重构（固定顺序便于扫描）

### 5.3 阶段变化触发 PROJECT.md 更新

仅以下事件触发 PROJECT.md 更新（避免每次小改动都动 PROJECT.md）：

- 完成一个里程碑（如"导出 PPT 功能完成"）
- 范围调整（如"砍掉周报功能"）
- 技术栈变化（如"接入 Vite"）
- 当前状态显著推进（v0.1 → v0.2）

### 5.4 与 commit 的关系

- 推荐：docs/ 变更与对应代码变更捆在**同一 commit**
- 不强制拆分独立 commit（避免噪音）
- commit message 不需要再写 changelog 内容（CHANGELOG.md 是 source of truth）
