# campaignreport.sk8s.cn 登录失败排查报告（交运维）

- 日期：2026-08-20
- 现象：用户在 https://campaignreport.sk8s.cn/ 用 admin@mediakit.local 登录，页面提示「邮箱或密码错误」
- 结论（开发侧已定位）：**与账号密码无关。server 容器处于崩溃重启循环，web 容器的 nginx 连不上 4000 端口，对 `/api/*` 与 `/uploads/*` 全部返回 502**；前端把一切登录失败都显示为「邮箱或密码错误」，掩盖了真实错误。

---

## 一、已完成的排查（无需重复）

| 探测 | 结果 | 说明 |
|---|---|---|
| `GET /`（前端静态页） | 200 | web 容器存活，nginx 正常运行 |
| `POST /api/auth/login`（重试 3 次） | 502（稳定复现） | 未到业务逻辑 |
| `GET /api/health` | 502 | 非登录接口问题 |
| `GET /uploads/test.png` | 502 | 整个 upstream 不通，非单接口问题 |
| 502 响应签名 | `nginx/1.30.4` + `x-envoy-upstream-service-time: 0` | 请求已穿过 ingress/envoy 到达 web 容器内 nginx，nginx 转发瞬间被拒（connection refused） |
| Sealos 控制台 | server 容器崩溃重启中（用户已确认） | 与上面全部证据吻合 |

**已排除**：账号密码问题；域名/网关/证书问题；web 镜像 `API_UPSTREAM` 注入问题（若 upstream 名解析失败，nginx 会启动失败，ingress 应返回 503 而非 502；现在 nginx 活着，说明名字可解析、只是后端没监听）。

**背景**：8-19 提交 e23af70 修复过一版「K8s 环境 /api 502」（web nginx 代理目标改为运行时由 `API_UPSTREAM` 环境变量注入）。该修复已推送 main，GitLab CI 自动构建 `latest` 镜像。当前 web 侧行为符合新版镜像特征，**问题收敛到 server 容器本身起不来**。

---

## 二、请运维排查（按优先级）

> 以下命令均可在 Sealos 控制台内置终端（kubectl）执行；_namespace 请替换为 campaignreport 应用所在命名空间。

### 1. server 容器为什么崩（最关键，一步定位）

```bash
kubectl get pods -n <namespace>                          # 看 RESTARTS 计数、STATUS
kubectl describe pod <server-pod> -n <namespace>         # 看 Last State / Exit Code / Events
kubectl logs <server-pod> -n <namespace> --previous      # 上一次崩溃的日志（关键）
```

server 镜像入口是 `docker-entrypoint.sh`，启动分两步，日志里按出现内容对号入座：

| 日志特征 | 根因 | 修法 |
|---|---|---|
| `Missing required env var: DATABASE_URL` | 环境变量缺失（config 校验直接抛错） | 见第 2 步补齐 |
| `[FATAL] JWT_ACCESS_SECRET is required in production`（或 JWT_REFRESH_SECRET） | 生产模式强制要求 JWT 密钥，未配置 | 补环境变量 |
| `[entrypoint] ERROR: prisma migrate deploy failed` + `P1001: Can't reach database server` | 数据库地址从集群内不可达（常见：写了 localhost / 内网 IP / 端口不对） | 核对 DATABASE_URL 指向集群可达地址，见第 3 步 |
| `[entrypoint] ERROR: prisma migrate deploy failed` + `P1000: Authentication failed` | 数据库账号密码错 | 核对凭据 |
| `[entrypoint] ERROR: prisma migrate deploy failed` + `Unknown authentication plugin` 或 `sha256_password` 相关 | MySQL 用户认证插件与 Prisma 5.22 不兼容（该项目历史上踩过：需 `ALTER USER ... IDENTIFIED WITH caching_sha2_password`） | DBA 改插件或换用户 |
| 完全没有 `[entrypoint]` 日志 | 部署的还是旧镜像（没有该入口脚本） | 确认镜像 tag 是 CI 新构建的 `latest`（e23af70 之后） |

### 2. 核对 server 容器环境变量

必需（缺一即崩）：

- `DATABASE_URL`（MySQL 连接串）
- `JWT_ACCESS_SECRET`
- `JWT_REFRESH_SECRET`
- `NODE_ENV=production`

建议核对（影响功能但不阻断启动）：`REDIS_URL`、`REDIS_DB`、`CORS_ORIGIN`、`COOKIE_SECURE=true`、`COOKIE_DOMAIN`、`WEB_URL=https://campaignreport.sk8s.cn`、`STORAGE_DRIVER`（local 时需挂载 uploads 卷）。

只核对 **key 是否存在**即可，勿将 value 发回。

### 3. 数据库连通性（如日志指向 P1001）

从集群内任一 pod 验证（比本机测试更真实）：

```bash
kubectl run netcheck --rm -it --image=busybox -n <namespace> --restart=Never \
  -- sh -c 'nc -zv -w 3 <DB_HOST> <DB_PORT>'
```

注意白名单：若 DB 在云白名单/安全组后，需放行 Sealos 集群出口 IP。

### 4. web → server 链路（仅当 server 恢复 Running 后仍 502 才需要）

- 确认 web 容器环境变量 `API_UPSTREAM` 的值 = server 服务在集群内的 DNS（形如 `<svc>.<namespace>.svc.cluster.local:4000`），与 Service 名一致；
- 确认 Service 端口映射到容器 4000。
